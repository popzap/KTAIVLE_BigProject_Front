# OmniSite — 프런트엔드

> **갈등시설을 어디에 놓을 것인가.** 그 질문에 지도 위의 좌표와, 그 좌표를 고른 이유를
> 함께 내놓는 B2G 공간의사결정지원 시스템(SDSS)입니다.
>
> 이 저장소는 **화면(Next.js)** 입니다. API 는 [백엔드 저장소](https://github.com/popzap/KTAIVLE_BigProject_Back)에 있습니다.

---

## 1. 무슨 문제를 푸는가

흡연부스, 재활용정거장, 소각장 같은 시설은 **필요하다는 데는 다들 동의하지만 내 집
앞은 안 된다**는 시설입니다. 지자체 담당자는 조례가 정한 배제 조건을 대조하고,
수백 개 후보지를 근거를 대며 줄이고, 주민 반발을 가늠하고, 결과를 결재 문서로
만들어야 합니다.

OmniSite 는 그 네 가지를 **한 흐름 안에서** 처리합니다. 조례를 읽어 배제 조건을
초안으로 내고 → **MCLP(최대 커버리지 입지 문제)** 로 후보를 Top-N 까지 줄이고 →
이해관계자 페르소나로 **공청회를 미리 돌려보고** → PDF·HWPX 로 내려줍니다.

시연 도메인은 **서울 용산구 흡연부스**(MVP), **성동구 재활용정거장**(2차) 두 개입니다.

## 2. 화면을 어떻게 쓰는가

화면은 여섯 걸음입니다. 처음부터 끝까지 한 번 지나가면 보고서가 나옵니다.

### 1 · 데이터 입력 — `/`

원본 데이터와 조례를 올리거나, 준비된 **프리셋(흡연 · 재활용)** 을 고릅니다. 처음
보는 사람은 프리셋으로 시작하는 게 빠릅니다.

### 2~3 · 감리 · 중요도 — `/audit` · `/audit/exclusion` · `/weights`

AI 가 조례를 읽고 **배제 조건과 데이터 의도를 제안**합니다. 여기가 이 서비스의 핵심
입니다 — **AI 는 초안만 내고, 확정은 사람이 누릅니다.** 사람이 멈춰서 손대는 지점이
두 곳 있습니다.

| 게이트 | 자리 | 사람이 정하는 것 |
|---|---|---|
| **A** | 감리 직후 | 배제 반경 · 데이터 의도 · 지역 코드 |
| **B** | 후보 생성 중간 | 집계 반경 `[R]` · 지표 가중치 `[W]` (−1 ~ +1 슬라이더) |

파이프라인이 "다시 돌려보세요"가 아니라 **그 자리에서 멈춰 사람을 기다립니다**(HITL).
문서에 남는 최종값은 언제나 사람이 누른 값입니다.

### 4 · 위치 선정 — `/sites`

MCLP 가 뽑은 Top-N 후보가 지도 위에 뜹니다. **지도가 있는 유일한 화면**입니다.
후보를 눌러 비교하고 최종 위치를 고릅니다.

> 지도는 Leaflet · Mapbox 같은 지도 라이브러리를 쓰지 않고 **canvas 에 직접
> 그립니다.** 의존성과 번들 크기를 늘리지 않으려고 내린 선택입니다.

### 5 · 갈등 예측 — `/hearing/select` → `/hearing` 또는 `/dynamic-hearing`

공청회를 미리 돌려봅니다. 토론 엔진이 **두 갈래**라, 먼저 `/hearing/select` 에서
고릅니다.

| | A · 대립 토론 `/hearing` | B · 다인 토론 `/dynamic-hearing` |
|---|---|---|
| 구성 | 찬성 · 반대 + 평가자 | 이해관계자 페르소나 N 명 |
| 쓰임 | 쟁점을 날카롭게 좁힐 때 | 누가 무엇 때문에 반대하는지 펼쳐볼 때 |

### 6 · 보고서 — `/report`

지금까지의 선택과 근거를 **PDF · HWPX** 로 내려받습니다. HWPX 에는 QR 이 들어갑니다.

| 모드 | 뜻 | LLM 호출 |
|---|---|---|
| `fixture` | 고정 기준선을 재생한다 (시연용, 대기 없음) | **0회** |
| `hitl` | 프리셋 데이터 + 사람이 게이트에서 확정 | 호출함 |
| `full` | 업로드한 데이터로 STEP0 부터 전부 | 호출함 |

**API 키 없이 시연하려면 `fixture`** 로 두세요. 흡연 도메인 기준 **약 95초** 만에
화면 5 까지 갑니다. 값이 매번 같고 비용이 0 입니다.

## 5. 실행 — 3줄

> 준비물: **Node.js 20.9 이상** (Node 24.16 / npm 11.13 에서 확인). 그리고 백엔드가
> 떠 있어야 합니다 → [백엔드 저장소](https://github.com/popzap/KTAIVLE_BigProject_Back)

```bash
cd BigProject_Front

cp .env.example .env.local     # Windows: copy .env.example .env.local
npm install
npm run dev
```

열립니다 → **<http://localhost:3000>**

`.env.local` 은 키가 **하나뿐**이고 기본값이 이미 맞습니다:

```
OMNISITE_API_ORIGIN=http://127.0.0.1:8000
```

브라우저는 백엔드 주소를 모릅니다 — 같은 출처(`/api/v1/...`)로만 부르고 Next.js
rewrite 가 넘깁니다. 백엔드를 다른 호스트에 두면 **이 한 줄만** 바꾸면 됩니다.

> 🔴 **반드시 `npm run dev` 로 띄우세요.** `npm run build && npm start` 로 띄우면
> 화면 5 토론만 내 로컬이 아니라 **운영 서버**로 나갑니다. 터지지 않고 값만 남의
> 것이 되기 때문에 알아채기 어렵습니다.

## 6. 자주 나는 오류

| 증상 | 원인 | 처치 |
|---|---|---|
| 화면 1 에 **「도메인 목록을 못 받았습니다 · 500」** | 백엔드가 안 떠 있음 | 백엔드 기동 → 화면의 **「다시 시도」** |
| 화면은 뜨는데 **지표가 전부 0** | 경계 `.shp` 없음, 또는 서울·경기 밖 지역 | 백엔드 README 데이터셋 절 |
| 화면 5 가 **HTTP 500** 인데 백엔드는 멀쩡 | 프록시 타임아웃 | 이미 6분으로 늘려 뒀습니다. 그래도 나면 백엔드가 6분을 넘긴 것 |
| 🔴 화면 5 토론이 **내 로컬이 아닌 운영 서버**에서 돎 | `build && start` 로 띄움 | **`npm run dev`** 로 |
| `npm install` 실패 | Node 버전 | Node 20.9 이상 |
| dev 서버가 500 `Unexpected token ':'` | dev 를 띄운 채 `build` 를 돌림 | `.next` 삭제 후 dev 재시작 |

> 백엔드 없이 프런트만 먼저 띄워도 됩니다. 흰 화면이 되지 않고, 값을 받아야 하는
> 자리마다 **화면 안에 사유와 HTTP 코드**를 적습니다. 가짜 값으로 채우지 않습니다.
